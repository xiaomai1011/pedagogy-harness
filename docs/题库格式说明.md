# 题库格式与交接说明（给岗位 4-A）

> **出具方**：岗位 1（负责人 / 技术）｜**日期**：2026-10-17
> **依据**：`docs/contracts.md` §2（**冲突时以契约为准**）｜**校验工具**：`tools/validate_questions.py`

---

## 一、一句话

把每一道题写成 `data/questions/<id>.json`，**放进去就能用**：

- 服务重启后，题目**自动出现在界面左侧题单**（不用改任何代码）
- 判题按 `test_cases` 跑；教学组件的错误分类按 `knowledge_points` 映射
- 日志自动带上 `phase`（前测 / 练习 / 后测）——**前端传不进来，也不用你传**

**照着 `data/questions/P001.json` 抄格式即可**（那是随仓库提供的样例题，可保留可替换）。

---

## 二、要交什么（题单结构）

**前后测同一场次**：前测 → 练习 → 后测，一次性做完。

| 阶段 | `phase` 取值 | 数量 | 说明 |
|---|---|---|---|
| 前测 | `pretest` | **3 题** | 进练习前测一次，测基线 |
| 练习 | `practice` | **6～8 题** | 主练习区，教学组件在这一段起作用 |
| 后测 | `posttest` | **3 题** | 练完立刻测，与前测**平行等值** |

**平行等值怎么算**（前测 / 后测两套题）：

- ✅ 覆盖**同样的知识点**、**同样的难度**（`difficulty` 逐题配对）
- ✅ 题面表述**不同**、用例输入数据**不同**（避免被试记住答案）
- ❌ 不要把前测题原样复制成后测题

## 三、字段表

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一，`P001` 递增；**必须与文件名一致**（`P001.json` ↔ `id: "P001"`） |
| `title` | ✅ | 题目名 |
| `statement` | ✅ | 题面（Markdown 可） |
| `examples` | ✅ | 可见示例，**至少 1 条**，每条含 `input` / `output`（`explain` 可选） |
| `test_cases` | ✅ | 判题用例，**至少 1 条**；每条 `input` / `expected`（都是**字符串**）/ `hidden`（布尔） |
| `reference_solution` | ✅ | 参考解源码。**后端不会下发**（`/api/questions/{id}` 已剥离），也不会喂给大模型 |
| `knowledge_points` | ✅ | 非空字符串数组。错误分类器靠它把错误映射到知识点 |
| `difficulty` | ✅ | `1` 基础 / `2` 中等 / `3` 较难 |
| `phase` | ✅ | `pretest` / `practice` / `posttest`（**取值只有这三个**） |
| `error_samples` | ⬜ | 可选。给"错误分类准确率"做测试用：`code` / `error_type`（`none`/`syntax`/`runtime`/`timeout`/`wrong_output`）/ `knowledge_point` |

### `hidden` 用例

- `hidden: false` → 学生能在题目详情里看到输入与期望输出
- `hidden: true` → **不回显输入与期望**（防学生直接对答案）
- 建议每题留 **1～2 条** `hidden: true`。**全部可见会让题目失去区分度**（校验脚本会提醒）

## 四、自检（**交题前请先跑**）

```powershell
python tools/validate_questions.py                    # 校验 data/questions/ 下全部题目
python tools/validate_questions.py data/questions/P001.json   # 只校验指定文件
```

- 输出 `[错误]` → **必须修**（字段缺失、类型不对、`phase` 非法、`id` 与文件名不一致…）
- 输出 `[警告]` → 建议修，不阻塞（没有隐藏用例、`error_samples` 的知识点不在列表里…）
- **退出码 0 = 全过**。错误为 0 才算合格交付。

## 五、怎么交

仓库是 **Private**，需要负责人先把你加为 **collaborator**（按你的 GitHub 用户名发邀请，你在邮箱接受）。

```powershell
git clone https://github.com/xiaomai1011/pedagogy-harness.git
cd pedagogy-harness
git checkout -b feat/questions
# 把题目放进 data/questions/，然后先跑一遍校验脚本
git add data/questions
git commit -m "feat(questions): 交付前测/练习/后测题组"
git push -u origin feat/questions
```

推完在 GitHub 开 **Pull Request**。若暂时用不了 git，把 `data/questions/*.json` 打包发给负责人代提交——**题目是你写的，贡献照记在你名下**。

## 六、红线

- ❌ **不要把答案写进 `statement` / `examples`**（题面里出现完整代码等于泄答案）
- ❌ **不要给 `expected` 与 `hidden` 用例**做任何对外接口（后端已剥离，你只管写文件）
- ❌ **不要改别人的文件**：`app/`、`web/`、`docs/contracts.md` 都别动（题库只放 `data/questions/`）
- ⚠️ **`reference_solution` 必须真能跑通全部用例**——它会被人对拍，跑不通说明题本身有问题
- ⚠️ 有疑问**先问负责人**，不要自己改字段名或加新字段（接口是冻结的）

## 七、常见会被校验抓出来的问题

| 现象 | 原因 |
|---|---|
| `id 与文件名不一致` | 文件名是 `P01.json` 但 `id` 写的是 `P001` |
| `phase 必填` | 漏写 `phase`（或写成 `postTest`、`pre`、`练习` 等） |
| `input / expected 必须是字符串` | 写成了数字，如 `"expected": 3`（应写 `"3"`） |
| `test_cases 至少 1 条` | 题目只有 `examples`，没有判题用例 |
| `没有任何 hidden=true 的用例` | 全部用例可见 → 建议补隐藏用例 |
| `knowledge_point 不在列表里` | `error_samples` 里写的知识点与 `knowledge_points` 对不上 |
