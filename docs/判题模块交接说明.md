## 2. 冻结的接口（不能改）

### 输入

```python
judge(question: dict, code: str, language: str = "python") -> JudgeResult
```

- `question`：题目字典，里面有 `test_cases`（测试用例列表），每项形如
  `{"input": "1 2", "expected": "3", "hidden": false}`
- `code`：学生提交的代码（一个字符串）
- `language`：语言，当前只有 `"python"`

### 输出 `JudgeResult`（字段一个都不能少）

| 字段 | 类型 | 你必须填的内容 |
|---|---|---|
| `status` | str | `pass` / `fail` / `timeout` / `crash` / `error` |
| `total_cases` | int | 用例总数 |
| `passed_cases` | int | 通过的用例数 |
| `failed_cases` | list | 未过用例，每项 `{case_index, input, expected, actual, hidden}`；`hidden=true` 的**不回显** input/expected |
| `error_type` | str | **执行层**类别：`none`/`syntax`/`runtime`/`timeout`/`wrong_output` |
| `stderr` | str | 子进程的错误输出原文 |
| `stdout` | str | 子进程的输出（**截断到 2000 字符**） |
| `exec_ms` | int | 耗时（毫秒） |
| `exit_code` | int 或 None | 进程退出码；超时被杀的填 `None` |

> ⚠️ **`error_type` 和 `stderr` 是契约红线**：它们是错误分类器的输入，缺了会导致别人返工。

## 3. 我已替你定死的 4 个参数（不用你自己拍脑袋）

这 4 条以前没写清，现在写死，照做即可：

| 项 | 定死的规则 |
|---|---|
| **超时阈值** | **每个用例 5 秒**；写成文件顶部常量 `TIMEOUT_SECONDS = 5`，方便以后调 |
| **输入怎么喂** | 把用例的 `input` 字符串（末尾补一个换行）**写进子进程的 stdin** |
| **用哪个解释器 / 工作目录** | 用 `sys.executable`（就是当前虚拟环境里的 python）；工作目录用系统临时目录，**不要在当前仓库里跑** |
| **输出怎么算"对"** | 先**规范化**再比对：① `\r\n` 统一成 `\n`；② 去掉每行行尾空白；③ 去掉末尾多余空行；④ 大小写**不**忽略。规范化后完全相等才算过 |

**不做浮点容差**（初学题都是整数输出）。以后要容差，由题库在题目里加字段，不要你在这里偷偷放宽。

### `error_type` 到底怎么判（照这个表）

| 情况 | `status` | `error_type` |
|---|---|---|
| 全部用例通过 | `pass` | `none` |
| 代码没跑起来（`SyntaxError` / `IndentationError`） | `fail` | `syntax` |
| 跑起来但中途抛异常（`stderr` 里有 `Traceback`） | `crash` | `runtime` |
| 超过 5 秒被杀 | `timeout` | `timeout` |
| 正常结束，但输出对不上 | `fail` | `wrong_output` |
| 判题系统自身出问题（题目没配用例、解释器找不到…） | `error` | `runtime` |

> `crash` 和 `error` 的区别：**`crash` = 学生的代码崩了**；**`error` = 我们的判题器出问题了**。别混。

## 4. 三种边界情况（分工表明确要求的，10/25 前完成）

1. **超时中断**：学生写了死循环 → 5 秒后杀掉进程 → `status=timeout`、`exit_code=None`
2. **程序崩溃 / 非零退出**：学生代码抛异常 → `exit_code != 0` → `status=crash`、`error_type=runtime`
3. **输出规范化比对**：学生输出 `"3 \n"`（多余空格），期望 `"3"` → 规范化后应判**通过**

---

## 5. 安全红线（这条最重要，别偷懒）

你跑的是**学生随手写的代码**，可能是死循环、可能是疯狂打印一百万行。

- ✅ **必须**用 `subprocess` + `timeout=` 控制时间（分工表要求的"子进程 + 超时"就是这个意思）
- ✅ **必须**限制 `stdout` 长度（超长就截断，别把内存吃满）
- ✅ **必须**在临时目录里跑，别在仓库目录跑
- ❌ **禁止**引入 Judge0、isolate 等第三方判题服务（部署与理解成本高，答辩会被问倒）
- ❌ **禁止**把学生代码用 `eval()` / `exec()` 在你自己进程里跑——一定要**开子进程**

> 为什么一定要子进程？因为**死循环会卡死你的整个程序**。开子进程后，超时就能把它单独杀掉，主程序没事。

## 7. 你要顺便学到的知识（按需要查，别死记）

| 概念 | 一句话是什么 | 为什么这里要用 |
|---|---|---|
| `subprocess` | 启动另一个进程 | 把学生代码隔离出去跑，崩了/卡了不影响主程序 |
| `timeout` | 给进程设最长运行时间 | 防死循环 |
| `stdin / stdout / stderr` | 程序的标准输入 / 输出 / 错误 | 输入喂给程序；输出用来比对；错误用来判断错在哪 |
| `exit code`（退出码） | 进程结束时的状态码，0 = 成功 | 判断程序是否"跑崩了" |
| 输出规范化 | 把无关的空白差异抹平再比对 | 避免"格式不同但答案对"被误判为错 |
| 单元测试（pytest） | 自动跑一批预设用例 | 改完代码能一键确认没弄坏 |
