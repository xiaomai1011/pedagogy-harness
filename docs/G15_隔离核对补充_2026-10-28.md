# G15 隔离核对补充：残留目录与故障处理（2026-10-28）

本轮只回答两个已暴露问题：**任务目录残留是否可被下一个任务读到**、**worker 被杀死后是否会停止执行并受控恢复**。
不扩展安全范围，不改申报书，不恢复校园网监听。

## 1. 任务目录里到底有什么

每个用例一个独立目录 `/run/ph-judge/work/case-*`，内容只有本次用例自己的：

- `main.py`（学生代码）
- `.stdin`（该用例输入）
- `.stdout` / `.stderr`（本次输出）

隐藏用例的**期望输出不落盘**：题目文件由 root 预拷到 `/run/ph-judge/questions`，worker 启动时读入内存并立即删除磁盘副本；执行期目录里没有答案，也没有其他参与者的数据。

## 2. 清理：正常、超时、异常、崩溃四种情况

| 情况 | 处理 |
| --- | --- |
| 正常结束 / 超时 / 异常退出 | `run_case` 的 `finally` 里删掉本用例目录，并**清空整个工作根目录**（学生代码与本进程同 uid，可能把文件写到 `tmpdir` 之外），再核对根目录确为空 |
| 清理失败 | `cleanup_status` 置为 `rm_failed/rm_denied`，worker 进入**降级状态**：后续任务一律拒绝（`cleanup_failed`），agent 转 503，宿主映射为 `rm_failed` 受控码，**不返回可继续接收新任务的正常状态** |
| worker 被强杀 | systemd `KillMode=control-group` 连同 cgroup 内的学生进程一并终止；重启时**先清空工作根目录**，清不干净就拒绝启动（退出码 3），由 systemd 重试 |
| 服务重启 | 启动清理失败则不启动；成功才监听 socket |

### 实测证据（真实 HTTP，非 mock）

修复前后各跑一次「任务 A 写标记 → 任务 B 读工作目录」：

- 修复前：`B` 读到 `LISTING=case-aiucml36,escape_marker.txt`、`MARKER=A-escape` ⇒ **确实存在跨任务可读残留**。
- 修复后：`B` 只看到自己的 `case-*`，`MARKER=<absent>`；工作根目录 `ls -A` 为空。

修复内容：每次任务结束清空工作根目录 + 启动时清理 + 清理失败降级拒单 + agent 将 `cleanup_status != ok` 映射为 503 `cleanup_failed` + 适配器映射为 `rm_failed`。

## 3. 故障处理：worker 被杀之后

受控测试（提交一个 `sleep 25` 的任务，运行中 `kill -9` worker 主进程）：

| 时刻 | 观察 |
| --- | --- |
| 杀死前 | worker `8323` + 学生进程 `8432`（`/run/ph-judge/work/case-*/main.py`） |
| 3 秒后 | **phcode 无任何残留进程**（cgroup 一并终止）；unit 为 `activating` |
| 11 秒后 | unit `active`，新 PID `8519`，工作根目录 **0 项** |

worker 停止期间向 agent 发请求：返回 **HTTP 503**（客户端看到 `HTTPError 503`），不是伪造的 pass/fail；恢复后同一请求正常 `pass`。

## 4. 结论表述（按评阅要求收紧）

- ~~“管理 HTTP 无任意执行入口”~~ → **没有绕过认证的通用命令入口；受认证的执行接口只应通过受限 worker 执行学生代码。**
- ~~“学生不能接触管理接口”~~ → **学生可以连接本地 socket，但请求被对端身份校验拒绝；实际受限执行路径的 IP 网络访问被阻断。**

## 5. 仍然存在的有界风险（记录，不作为阻塞项）

1. worker 与学生代码同为 `phcode`：学生代码可向 worker 发信号造成中断（可用性影响，不泄露凭证、读不到 worker 内存）；本轮已保证中断后**停止执行、清理并受控恢复**。
2. token 无自动轮换：存储 0600 属主 `phagent`、不进环境变量与日志；更换办法是重新生成文件并重启 agent，同时更新宿主副本。
3. 未验证 VM 多任务并发隔离；本实验按**单路**使用。

## 6. 复现命令

```text
# 交叉任务残留探针（宿主）
python cleanup_cross_task_probe.py

# 故障演练：运行中杀 worker
sudo -n kill -9 "$(systemctl show -p MainPID --value ph-judge-worker)"
systemctl is-active ph-judge-worker
pgrep -a -u phcode
```
