# 阶段 4：隔离能力实测记录（2026-10-28）

> 范围：VM `PH-Judge-VM`（Ubuntu 24.04.3，192.168.200.10）内的固定样例执行。
> 结论口径：**固定样例能执行 ≠ 隔离验收通过**；本文件只记录阶段 4.1/4.2 的实测证据，
> 正式隔离门（`tools/accept_isolation.py` 集成项）仍未执行，演示站仍保持 fail closed。

## 1. 执行身份（4.0）

| 项目 | 结果 |
| --- | --- |
| agent 进程身份 | `phagent`（uid 999，组 `phagent` + `ph-judge`，`/usr/sbin/nologin`） |
| 执行进程身份 | `phcode`（uid 996，gid 987，组 `987` + `ph-judge`，home `/var/lib/ph-code`，nologin） |
| 可否 sudo | `sudo -l -U phcode` → `User phcode is not allowed to run sudo on phjudge.`；学生进程内 `sudo -n true` → `sudo-rc=1` |
| 是否在 sudo/docker 组 | 否（两者的补充组只有 `ph-judge`） |
| 能否读 token | `denied: /etc/ph-judge-agent/token PermissionError` |
| 能否读管理私钥 | `denied: /home/phjudge/.ssh/id_ed25519 PermissionError`（`ProtectHome=yes`） |
| 能否改 agent 程序 | `write-denied: /opt/ph-judge-agent/tamper.txt OSError`（`ProtectSystem=strict`，只读） |

agent 与 worker 通过 Unix socket `/run/ph-judge/worker.sock`（`srw-rw---- phcode ph-judge`）通信，
worker 用 `SO_PEERCRED` 只接受 uid 等于 `phagent` 的连接；**agent 自己不执行任何代码**。

## 2. 固定样例（4.1）

请求 `POST /v1/execute {"fixture": "<name>"}`，宿主 → `http://192.168.200.10:9443`：

| 样例 | 状态 | 关键结果 |
| --- | --- | --- |
| `print_ok` | pass | `ok`，16 ms |
| `exit_zero` | pass | 正常退出，exit 0 |
| `timeout_loop` | timeout | exit `-9`，5002 ms，`cleanup_status=ok` |
| `output_flood` | pass | `stdout` 截断到 2000 字符 |
| `spawn_child` | pass | 415 ms；孙进程被整组清理，`cleanup_status=ok` |
| `identity_probe` | pass | `uid=996 gid=987 groups=[987, 1001]`、`sudo-rc=1` |
| `network_probe_local` | pass | `agent-blocked: TimeoutError`（连本机 9443 都不通） |
| `network_probe` | pass | `network-blocked: TimeoutError`（192.168.200.1:22） |
| `token_probe` | pass | token / capabilities 均 `PermissionError` |
| `file_probe` | pass | 三个目标目录写入全被拒；`cwd=/run/ph-judge/work/job-*` |
| `memory_probe` | pass | 申请 400 MB → `MemoryError`（`RLIMIT_AS=256 MB`） |
| 请求体带 `code` | 503 | `agent_rejected`「阶段 4 只接受内置固定样例」 |

**注意**：`/v1/execute` 目前只接受 `{"fixture": name}`，任何 `code`/`question` 都不会被执行。

## 3. 禁网 A/B（可归因）

同一段 `connect(("192.168.200.10", 9443))` 探针，用 `systemd-run --uid=phcode` 起：

| 条件 | 结果 |
| --- | --- |
| 不设 `IPAddressDeny` | `OPEN` |
| `-p IPAddressDeny=any` | `BLOCKED TimeoutError` |

worker 单元实际属性：`IPAddressDeny=::/0 0.0.0.0/0`、`MemoryMax=536870912`、`TasksMax=48`、
`User=phcode`、`SupplementaryGroups=ph-judge`、`NoNewPrivileges=yes`、`ProtectSystem=strict`、
`ProtectHome=yes`、`PrivateTmp=yes`。

## 4. 资源与清理

- 每请求独立临时目录 `/run/ph-judge/work/job-*`（0700，属主 `phcode`），结束后 `shutil.rmtree`；
  清理失败会写 `cleanup_status=dir_cleanup_failed: <类型>`，不会伪装成成功。
- 超时后 `os.killpg(SIGKILL)` 清整组，并等 2 秒确认无残留；仍有残留则报 `leftover_processes`。
- stdout/stderr 落文件而不是管道——上一版用管道时，孙进程持有管道会让父进程假超时（实测 8.1 s / 15 s 才返回），
  这是改成文件的直接原因。
