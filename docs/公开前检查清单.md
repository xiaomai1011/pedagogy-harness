# 公开仓库前检查清单

> 结论先行：**当前不建议直接把本仓库改成 Public。** 下面列出阻塞项与两条可行路径。
> 本文件本身可以随仓库公开，不包含敏感值。

## 已选路径（2026-10-29）

采用**路径 A**：本仓库先保持私有，待试用与比赛材料结束后再公开。触发条件与执行顺序：

1. 触发条件（三项同时满足）：本轮试用数据已收齐并分析完；比赛/申报材料已提交；负责人确认可以公开。
2. 执行前先跑只读检查：`python tools/check_release_readiness.py`，要求 **0 个阻塞项**。
3. 轮换所有用过的密钥与令牌（模型 Key、访问码签名密钥、VM agent 令牌、管理台令牌），再跑一次检查。
4. 选定并添加 LICENSE（MIT / Apache-2.0 / 其它），更新 README 的「当前阶段」与「许可」两节。
5. 最后由仓库所有者把可见性改为 Public；改完核对 README 渲染、Issues/ Wiki/ Actions 设置。

在此之前不要 `git rm` 题库或导出文件——它们已经在历史里，删除不会让历史变干净，反而丢失本轮证据。

## 一、当前阻塞项

1. **题库会泄露**
   `data/questions/*.json` 含 19 道题的参考解与隐藏用例，且已经进入 git 历史（3 个提交）。
   一旦公开，任何人都能拿到全部答案；本轮及后续试用/测量的题目效度会直接失效。
   注意：删文件只能影响后续提交，**历史里的内容仍然可见**。

2. **内部文档与内网信息**
   `docs/` 有 33 个受版本控制的文件，其中 14 个提到申报书；G12–G16 等验收记录写有内网地址
   （如 `10.30.34.22`、`192.168.200.x`）、VM 与令牌文件路径、验收细节。这些对公开仓库不合适。

3. **没有许可证**
   未声明 LICENSE 时默认「保留所有权利」，公开也无法被合法复用。

4. **需确认外部规定**
   竞赛/学校对作品公开发布、查新与申报口径可能有要求，这一步只能由负责人确认。

（`web/vendor/monaco` 约 24 MB，只是体积问题，不阻塞。）

## 二、两条路径

### 路径 A：等试用/比赛结束后再公开本仓库（推荐）

适用：希望保留完整开发历史与验收记录。

1. 轮换所有用过的密钥与令牌（模型 Key、访问码签名密钥、VM agent 令牌、管理台令牌）；
2. 用 `git log --all -p` 人工复核历史里没有密钥、访问码、真实参与者数据；
3. 确认题库是否已可公开（例如本轮测量已结束、题目不再复用）；
4. 加 LICENSE，更新 README 的「当前阶段」；
5. 再把仓库改为 Public。

### 路径 B：新建「展示仓库」（全新历史）

适用：现在就想公开，但不能泄露题库与内部记录。

1. 新建仓库，只复制 `app/`、`web/`（不含 vendor 亦可）、`tests/`、`tools/`、`vm_agent/`、`README.md`、
   `SECURITY.md`、`docs/contracts.md` 等可公开文档；
2. 题库放 2–3 道**示例题**（自拟，不含本轮测量题与隐藏用例）；
3. 不复制 `.git`，历史从零开始；
4. 加 LICENSE 后再公开；
5. 本仓库保持私有，作为开发与验收记录。

## 三、公开前逐项检查

- [ ] 全历史扫描：`git log --all -p | rg -i "sk-|api[_-]?key|secret|password|token"`

- [ ] `docs/exports/`、`data/backups/`、`*.sqlite`、`*.log` 未被跟踪
- [ ] 所有曾经用过的密钥已轮换
- [ ] 无姓名/学号/手机号/邮箱等个人信息
- [ ] LICENSE 已选定
- [ ] README 的「当前阶段」与事实一致（不写「效果已证明」）
- [ ] 仓库设置：是否启用 Issues / Wiki / Actions 已确认
- [ ] 负责人确认竞赛与学校口径允许公开
