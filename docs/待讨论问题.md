## Q1 提示入口跑判题 = 一个「不计数的代码执行入口」

### 文件事实

- [pipeline.py:63](file:///D:/Downloads/Trae-workspace/pedagogy-harness/app/harness/pipeline.py#L63)

### 实测

3 次正式提交 + 连点 5 次纯提示 → `submission_log` **恒为 3 行**，判题实际执行 **8 次**。

### 我的判断（非文件要求）

「提交次数 / 失败次数」**完全不涨** → 研究会低估这两个指标；
同时这是一个**绕过提交计数做试错**的通道。
C 的提示事件日志能记到"请求了几次"，但「**判题执行了几次**」将来无处可查。

### 岔路与我的倾向

| 选项 | 内容 | 我的评价 |
|---|---|---|
| a | 现状不动，报告里声明 | 数据将来解释不了，不推荐单独使用 |
| b | 提示入口**不判题**，复用该被试该题上次提交的判题结果 | **反对**——学生改了代码没提交时，提示针对旧代码，功能价值受损 |
| c | 照跑，但新增「判题执行次数」计数，与提交次数分列 | 倾向 |
| d | 照跑，并在 C 的日志里标「本次触发了判题执行」 | 倾向 |

**要你定什么**：选 a/b/c/d。无论选哪个，建议保证「判题执行次数」可查。

## Q3 H 的修法会和「提示阶梯要能用」直接打架

### 文件事实

- R1 的围栏判据**只在 `blocks` 非空时**触发（[leak_guard.py:83](file:///D:/Downloads/Trae-workspace/pedagogy-harness/app/harness/leak_guard.py#L83)）；

- R3 **只数围栏内**的行数（[88-91](file:///D:/Downloads/Trae-workspace/pedagogy-harness/app/harness/leak_guard.py#L88-L91)）。
- R4 需参考解 ≥ 20 字符且最长公共子串占比 ≥ 50%（[22-24](file:///D:/Downloads/Trae-workspace/pedagogy-harness/app/harness/leak_guard.py#L22-L24)、[94-98](file:///D:/Downloads/Trae-workspace/pedagogy-harness/app/harness/leak_guard.py#L94-L98)）。

→ **无围栏 + 换写法 + 短解法**：四个判据**全部不触发**。
所以任务单 H 表里"与参考解**不同写法**的完整解法"那条期望"拦住"，**按现实现必然漏网**。

### 张力

硬约束同时要求两条，而无围栏场景下它们互相拆台：

1. 「防泄优先**不漏网**，命中任意一条即拦截」；
2. 「提示阶梯要循序渐进，**L4 允许给局部片段**」。

### 岔路与我的倾向

| 选项 | 无围栏时的策略 | 代价 |
|---|---|---|
| a | 从严，宁可误拦 | 阶梯末端（L4）可能被废掉 |
| b | 只拦"看起来是完整可运行脚本"的 | 阈值难定，仍可能漏 |
| c | **按等级分层：L1–L3 从严、L4 从宽** | 需要写清"完整"的判定口径 |

**我的倾向：c**。理由：L1–L3 的定位本就是"不给代码"，误拦代价只是少说两句话；
L4 的定位是"给局部片段"，误拦会把整条阶梯的价值削掉。

**要你定什么**：
1. 选 a/b/c；
2. 确认对外措辞边界——**只能说"做了可解释的程序化约束、降低直接答案暴露风险"，
   不能说"绝不泄露答案"**（H 的结论直接决定材料与答辩措辞）。

## 附：一处自我纠正（已修，记录备查）

评阅转述中有「7 次失败**连点即可拿到** L4」的说法，**该说法不成立**。

**实测**：3 次正式失败后**连点 5 次**纯提示，返回等级依次 `[2, 2, 2, 2, 2]`（**不累进**），
提交日志恒为 3 行。原因是 `consecutive_fail` 只在提交入口落库、提示入口不落库。

**结论**：
- 原 A 的「连点不升级」**仍然成立**（那次修的是"按上次展示等级递进"）；
- 本次缺陷性质不同——是**恒定 +1 偏移**（每次纯提示请求返回的等级比应给的高一级）；
- **两者不得混为一谈**，否则技术方与评阅方会各说各话。
