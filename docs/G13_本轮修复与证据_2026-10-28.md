## 1. 提示阶梯：主动请求可升一级（已改实现 + 状态转换测试）

规则（`app/harness/hint_ladder.py::next_state`）：

| 情形 | 行为 |
| --- | --- |
| 首次请求 | 显示 L1 |
| 再次主动请求「进一步提示」 | 每次最多 +1，上限 L4 |
| 连续 2 次正式失败 | 解锁 +1（每 2 次一级） |
| 请求与失败同时满足 | 只升一级（不叠加跳两级） |
| 纯提示请求 | 不增加失败次数、不写错误记忆 |
| 页面刷新/网络重试/重复到达 | 同一 `hint_request_id` 幂等回放，不升级、不调模型 |
| 成功提交 | 不自动升级 |
| 切到新题 | 不继承另一题等级；回到旧题按该题历史 |

界面：`「请求提示」/「请求进一步提示」` 与 `「重看提示」` 分开；重看复用上次请求号（回放缓存）。帮助文案同步改写。
测试：`tests/test_hint_upgrade_flow.py`（6 项）+ `tests/test_hint_ladder.py`（改 4 项）+ `tests/test_pipeline.py::test_repeated_hint_requests_raise_one_level_each`。
不采用「累计两次请求才升一级」：申报书没有这道门槛。

## 4. 身份与阶段：服务端签发访问码（最小实现）

- `app/access.py`：`v1.<b64url(payload)>.<b64url(HMAC-SHA256)>`，payload=`{v,pid,batch,phases,iat,exp}`；密钥只从 `PH_ACCESS_SECRET` / `PH_ACCESS_SECRET_FILE` 读，**不进前端、不进仓库、不进导出**。
- 服务端从凭证确定参与者：`/api/submit`、`/api/hint` 都先验码再进单路锁；body 里的 `participant_id` 与凭证不一致 → 403 `identity_mismatch`。
- 阶段由服务端约束：按题目 `phase` 与凭证 `phases` 比对，越权 → 403 `phase_not_allowed`（判题与模型调用都不发生）。
- 缺失/过期/伪造/身份不符均拒绝；`PH_REQUIRE_ACCESS_CODE=1` 才强制（**默认关**，正式采集必须开）。
- 访问码不写普通日志、不放 URL 查询参数；测试 `tests/test_access_control.py` 8 项（含"强制模式下无码/伪造 403 且 judge 零调用"）。
- **限制**：HMAC 只防伪造，**不能防窃取和转发**；当前仍是明文 HTTP（校园网可嗅探）。在拿到受控传输条件前，只建议负责人监督下的本机核验，**不得宣称校园网访问已安全**。
