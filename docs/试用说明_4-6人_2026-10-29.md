# 小规模自由体验说明（4–6 人）

日期：2026-10-29　适用版本：`0.5.2-enroll` 及之后

> 邀请约 4–6 名未参与系统技术开发的同学，通过网址自由选择练习题、提交代码并体验教学提示；不要求统一时间、统一做题顺序或完成规定题量。依据实际使用记录和自愿反馈，进行小规模体验性验证与描述性分析。

本次不是统一评测：**不签到、不登记、不做姓名与编号对照表、不固定座位、不强制前后测**。

## 一、体验者怎么用

1. 打开网址即可，**不用填编号、不用访问码、不用登记**。
2. 页面自动分配一个匿名会话编号（`A00x`），存在本机浏览器 Cookie 里：刷新、关掉再开还是同一个号；换浏览器、清 Cookie、重装会得到新号，**不承诺识别同一个人**。
3. 自由选题、写代码、提交、请求提示；题量不限、顺序不限。
4. 页面顶部一行告知：本页面会记录代码提交、提示使用与判题结果，用于本次教学研究与改进；不收集姓名。

## 二、匿名会话的边界（写材料时要照此表述）

- 编号只用于**关联这台浏览器的使用记录**，不代表真人身份。
- **不按来源 IP 找回或合并会话**（已取消该做法）：多人共用校园网出口时不会串号。
- **会话数不等于参与人数**：同一人换设备/清 Cookie 会多出会话；多人共用一台电脑会共用一个会话。材料里“邀请 4–6 人”和“产生 N 个会话”分开写。
- 后台仍校验会话：没有会话 Cookie 的提交/提示请求直接拒绝（403 `session_required`），改请求体里的编号不能读别人的记录；管理台与导出接口仍只对本机 + 管理令牌开放。

## 三、题目与教学组件

- 题库**全部开放**（前测 3 题 S001–S003 + 练习 13 题 P001–P013 + 后测 3 题 S004–S006），体验者想先做哪道就做哪道。
- **前后测阶段不提供 AI 提示**（与正式机制一致：取提示返回 `phase_disabled`），练习阶段才有提示。
- 不要求按顺序做，也不要求做完前后测；**没做就是没做，不算缺考或失败**。
- 四级提示、错误分类、错误记忆、判题规则都**不改**。

## 四、数据与分析（描述性，不算学习提升）

看这些：

- 实际产生的**匿名会话数**、有提交的会话数；
- 访问/尝试过哪些题、提交次数、通过题目数；
- 提示请求次数、最高等级、生成来源（`llm` / `stub` / `fallback`）；
- 错误类型分布、判题与模型耗时、判题故障次数；
- 自愿提供的使用感受与问题反馈（线下收集，不建问卷模块）。

**不写成“教学效果提升”或“学习增益已证明”**；未出现的题目只是没做，不记为缺考或失败。分析工具会给出「按题成功率」和「只含同时做了前测与后测的会话」的配对对比，但这是自由选题下的观察值（非随机、无对照组、步骤与时点不统一），只能作描述，不做显著性检验、不宣称因果。

导出与分析：

```
python tools/export_experiment_data.py --db data/experiment_trial_20261029.sqlite \
    --out docs/exports/trial_20261029 --backup data/backups/trial_20261029.sqlite
python tools/analyze_trial.py --export docs/exports/trial_20261029 --mode free
```

产物：`participants_phases.csv`、`submissions.csv`（含代码原文）、`hint_events.csv`、`trial_participants.csv`、`trial_questions.csv`（按题成功率）、`trial_prepost.csv`（前后测配对对比）、`trial_summary.md`，外加一份一致性备份。

口径：`judge_ms`＝判题执行耗时，`model_ms`＝模型调用耗时，都不是作答时间；百分比写成“分子/分母”；4–6 人不做显著性检验，前后测对比只列同时做了两侧的会话。

## 五、运行边界

- 独立体验批次 `TRIAL-20261029` 与独立库 `data/experiment_trial_20261029.sqlite`，不混入开发自检与验收数据；旧库与旧记录不删。
- 管理接口仍需管理令牌且只允许本机访问；不放开管理接口。
- 真实 VM 判题、清理失败拒单、单路执行与防重复请求保持不变；单路繁忙时页面提示“服务正忙，稍后重试”，**保留已写代码**，不排队登记。
- 不改提示阶梯、分类、记忆与判题规则；不为这次调整扩平台。

## 六、负责人需要提供

1. 体验时间段与邀请方式（发给谁、怎么发网址）；
2. 是否维持“只放练习 13 题”，还是要再缩小到某几题；
3. 告知与同意的说法（口头/一页纸均可），数据保存期限；
4. 反馈收集方式（微信/口头/一页纸），由负责人整理；
5. 启动确认：版本、体验库路径、批次、身份模式（自动登记、无访问码）、单实例、VM 就绪、备份位置。

## 七、不做的事

不组织统一考试、不设统一评分、不做对照组或消融实验、不做显著性检验、不建问卷或用户管理模块、不改申报书与研究终稿。
